Создано 02.11.2026. Спецификация — [vitalo-ai.md](vitalo-ai.md), решения D-37, D-45, D-47. Текст
в коде — `apps/api/src/compat/ai.ts` (`SYSTEM_COMMON`, `SYSTEM_CART`), совпадает с этим документом; правка текста — сначала здесь, потом в коде. **Статус 02.11:** черновик у архитектора; окончательная версия — до проверки с ключом на тестовом боте.

Как устроено: **общая часть** одна для корзины (3.8) и чата (3.9), к ней добавляется **часть сценария**. Данные
(товары, правила, повторы) сервер подставляет в отдельном блоке `<данные>` — модель видит только их. Ответ модели
сервер проверяет (формат, запрещённые слова, товары в наличии) и сам поднимает метку при повторе вещества (D-47) —
это не зависит от инструкции.

## 2. Сценарий «Корзина» (3.8)

```text
СЦЕНАРИЙ: проверка совместимости корзины.

В данных: товары корзины (id, название, вещества), правила, которые срабатывают между РАЗНЫМИ товарами корзины,
предупреждения о лекарствах и список повторов — веществ, которые есть в нескольких товарах.

Что сделать:
1. Метка verdict:
   - "consult" — есть правило «не сочетать»;
   - "spread" — есть правило «разнести по времени» ИЛИ есть хотя бы один повтор вещества;
   - "compatible" — иначе. Предупреждения о лекарствах метку не меняют: покупатель о лекарствах не писал.
2. text — 2–3 предложения: что с чем сочетается и почему (по объяснениям правил), что разнести и на сколько часов.
   О повторах веществ в text не пиши — их показывает приложение отдельной строкой; повторы нужны только для метки.
   Не повторяй строку про лекарства — её показывает приложение.
   Если в корзине 2+ товара и между ними НЕТ правил и повторов — метка "compatible", а text начинается со слов
   «В наших правилах нет известных конфликтов между этими добавками» (по-узбекски: «Bizning qoidalarimizda bu
   qoʻshimchalar orasida maʼlum ziddiyatlar yoʻq»). Никогда не пиши «полностью совместимы» или «безопасно сочетать».
   Если есть правило «синергия» — объясни пользу сочетания по тексту правила.
3. timing — для КАЖДОГО товара корзины одна короткая строка, когда принимать: только время (утро, день, вечер,
   перед сном) и «с едой», «натощак», «за N минут до сна» — по правилам и памятке приёма товара. Количество
   (капсулы, таблетки) — только если оно дословно есть в памятке товара.
4. Если в корзине один товар: productIds — 2–3 товара из списка «можно предложить», которые по правилам «синергия»
   хорошо с ним сочетаются; text — коротко почему. Если подходящих нет — пустой список и «пока нечего добавить».
   Если товаров в корзине больше одного — productIds пустой.

Схема ответа:
{"verdict": "compatible" | "spread" | "consult",
 "text": "строка",
 "timing": [{"productId": "id", "when": "строка"}],
 "productIds": ["id"]}
```

**Правки архитектора 02.11:** нейтральная формулировка «нет известных конфликтов» вместо «совместимы»; новые
запрещённые слова («безопасно», «без побочных эффектов», «не имеет противопоказаний», «полностью совместимы» и
узбекские); время приёма без количества, если его нет в памятке; «вы» / «siz» и латиница; симптомы в чате (3.9).

**Изменения 02.11 (шаг 2, код):** правила «осторожно с лекарствами» в корзине метку не меняют — вещества товара никогда
не совпадают с группой лекарств, и иначе любой товар с железом был бы всегда красным; строку про лекарства приложение
показывает отдельно под ответом. Красная метка в корзине — только правило «не сочетать». Для одного товара модель
получает список «можно предложить» (до 10 товаров в наличии, связанных правилом «синергия»).

**Что сервер проверяет сам (не зависит от инструкции):** формат JSON; метка не ниже порога из правил и повторов
(D-47); время приёма есть для каждого товара; предложения — только из списка «можно предложить», не больше 3;
язык ответа (в узбекском — ни одной кириллической буквы); нет запрещённых слов; количество капсул или таблеток во
времени приёма — только если оно дословно есть в памятке; если между 2+ товарами нет правил и повторов, а начала
«В наших правилах нет известных конфликтов…» нет — сервер сам ставит его в начало. Не прошёл проверку — ответ не
показывается, корзина уходит специалисту.

## 2а. Сценарий «Вопрос по корзине» (Шаг 0б, D-68, D-69)

Код: `apps/api/src/compat/ai-goal.ts` (`SYSTEM_GOAL`, `GOAL_SCHEMA`, `checkGoalAnswer`). Покупатель ничего не пишет: только
чипсы — цель (сон, стресс, энергия, суставы, иммунитет, спорт), длительность (меньше 2 недель / 2–4 недели / дольше
месяца) и уточнение (три варианта на цель). В модель уходят выбранные чипсы, товары корзины с веществами и **одобренные**
строки таблицы «вещество → цель» (`goal_evidence`). Модель — настройка `goal_model` (по умолчанию Haiku).

Проверки кода до показа: каждый товар корзины ровно один раз; товар без строки базы — всегда «данных немного»
(`no_data`), что бы ни выбрала модель; уровень доказательности приложение берёт из базы и показывает словами (D-67);
запрещены обещания (общий список), названия болезней и диагнозов, «анализы», «лечение», единицы мг / мкг / МЕ.
Строку «Если проблема держится дольше 3–4 недель — обратитесь к врачу» и кнопку «Спросить специалиста VITALO»
добавляет приложение.

```text
СЦЕНАРИЙ: «Поможет ли этот набор для моей цели?» — вопрос покупателя по товарам его корзины.

Покупатель ничего не писал: он выбрал кнопками цель, сколько длится проблема и что именно беспокоит. Его ответы и
товары корзины — в данных. У каждого товара — вещества и строки НАШЕЙ базы доказательности «вещество → цель»: уровень,
когда помогает, когда не поможет. Строк может не быть.

Что сделать:
1. products — для КАЖДОГО товара корзины одна запись:
   - fit:
     "helps" — по строкам базы вещество товара может помочь именно при этой цели и этом характере проблемы;
     "maybe" — может помочь, но только при условии из строки «когда помогает» (например, при дефиците);
     "unlikely" — по строке «когда не поможет» это не тот случай или товар не про эту цель;
     "no_data" — у товара нет строк базы для этой цели.
   - text — одно-два коротких предложения простыми словами, почему так. Опирайся ТОЛЬКО на строки базы. Если строк нет —
     только «Данных немного: может помочь, если …» по составу товара в общих словах, без выдуманных фактов и цифр.
     Не называй уровень доказательности и не пиши «исследования доказали» — уровень показывает приложение.
2. Честность: если для цели хватает меньшего числа товаров — так и скажи в summary: какие товары можно не брать для этой
   цели. Не предлагай докупить другие товары.
3. summary — 1–2 предложения: общий вывод по набору для этой цели.
4. steps — 2–3 коротких общих шага без добавок для этой цели (например, для сна — режим, свет, кофеин, гаджеты перед
   сном; для энергии — сон, вода, движение). Без лекарств и без дозировок.
5. Не называй и не перечисляй возможные болезни или причины-диагнозы («это может быть…»), не советуй анализы и лечение.
   Строку про врача и кнопку «Спросить специалиста» приложение добавит само — не пиши их.
6. Медицинские термины (верхний уровень, мг, МЕ) не используй — пиши простым языком.
```

Схема ответа: `{ summary, products: [{ productId, fit: helps | maybe | unlikely | no_data, text }], steps: [2–3] }`.

## 2б. Сценарий «Спросить VITALO AI о корзине» — переписка (D-70)

Код: `apps/api/src/compat/ai-chat.ts` (`SYSTEM_CHAT`, `CHAT_SCHEMA`, `checkChatAnswer`, `hasRedFlag`) и
`ai-chat.service.ts`. Окно переписки в Mini App — `apps/miniapp/src/components/AiChat.tsx`. Модель — та же настройка
`goal_model` («Модель для переписки»); дневной лимит — общий с прежним «вопросом по корзине» (`chat_daily_limit`).

Что видит покупатель: сверху коротко корзина; подсказки от его лица — «О корзине» («Можно ли принимать их вместе?») и «Что
беспокоит» («Мне трудно заснуть — что из этого поможет?»), темы корзины первыми; своё поле до `chat_max_chars` (300)
символов; до `chat_max_turns` (6) вопросов в разговоре; внизу строка «VITALO AI работает в бета-режиме…».

Что уходит в модель: блок корзины (как в «Корзине»), одобренные строки «вещество → цель» для её товаров, при пустой
корзине — до 3 товаров каталога на цель из одобренных строк, последние 12 сообщений разговора, «осталось уточнений»
(не больше 2 на разговор) и сам вопрос. Телефоны и e-mail вырезаются до модели и до базы.

Ответ модели (JSON): `kind` — answer / clarify / off_topic / red_flag; `goal` — тема; `text`; `clarify_options` (2–4,
для уточнения); `products` — товары с `fit` и пояснением; `steps` (до 3); `followups` (до 3, от лица покупателя).

Проверки кода до показа: только товары корзины (или предложенные товары каталога при пустой корзине); метка `fit` для
цели — только из нашей базы (нет строки — «данных немного»; для вопросов совместимости метки нет); уточнение — только пока
есть лимит; запрещённые слова (обещания, диагнозы, дозировки — кроме цифр в названии нашего товара); язык ответа.
Не прошла проверка или модель не ответила — «Не получилось ответить… спросите специалиста».

Красные флаги (беременность и кормление, ребёнок, лекарства, боль в груди, кровь, сильная боль, мысли о самоубийстве —
RU и UZ) ловит код **до модели**: ответ — фиксированная строка «обсудите с врачом» и кнопка специалиста, запрос в модель
не уходит и в лимит не считается.

Хранение: `ai_chats` (номер `AI-ГГГГММДД-NNNN` по дате Ташкента) и `ai_chat_messages`; админка «VITALO AI → Переписки»
(администратор и специалист, каждое открытие — в журнале действий). Текст хранится `chat_retention_days` (365) дней,
затем стирается; покупатель может удалить переписку сразу.

Инструкция — в коде (`SYSTEM_CHAT`), здесь кратко: консультант аптечного уровня; уточнять только по существу и не больше
лимита; в ответе — прямой ответ с учётом прошлых сообщений, каждый товар корзины с пояснением по строкам базы, 0–3 общих
совета без добавок, 2–3 следующих вопроса от лица покупателя; пустая корзина — 1–3 товара из предложенных; вопрос не по
теме — вежливый отказ; строку про врача и кнопку специалиста добавляет приложение.

## 3. Сценарий «Чат» (3.9) — для справки, дорабатывается в 3.9

```text
СЦЕНАРИЙ: чат VITALO AI.

- Конкретный вопрос о товаре или веществе, сравнение товаров, вопрос о совместимости — ответь сразу (mode "answer"):
  факты из данных, 2–3 подходящих товара, 2–3 следующих вопроса в followUpPills.
- Широкий запрос («что мне попить?», «какие добавки подойдут именно мне?») — задай ОДИН уточняющий вопрос
  (mode "ask") с 3 вариантами в quickReplies, по порядку: цель → Vegan / Halal-сертификат → добавки или лекарства.
  Если покупатель уже ответил на шаг — пропусти его. После третьего шага — всегда ответ с товарами.
- Вопрос с симптомом («плохо сплю», «нет сил», «болит голова»): не толкуй симптом и не связывай его с болезнью;
  предложи товары по общей цели (сон, энергия и т. п.) и добавь: «Если симптом сильный или держится долго —
  обратитесь к врачу».

Схема ответа:
{"mode": "answer" | "ask", "text": "строка", "quickReplies": ["строка"], "productIds": ["id"], "followUpPills": ["строка"]}
```

## 4. Пример блока данных (корзина, RU)

```text
<данные>
язык: ru
товары корзины:
- id A003 | Витамин D3 2000 МЕ | вещества: Витамин D3 | памятка: 1 капсула утром с едой
- id A014 | Магний B6 | вещества: Магний, Витамин B6 | памятка: 2 таблетки вечером
- id A004 | Мультивитамины Duo | вещества: Витамин D3, Цинк, Железо, … | памятка: 1 капсула утром
правила между товарами:
- Магний + Витамин D3 | синергия | магний — вечер, D3 — утро | «Магний необходим ферментам…»
повторы веществ (только для метки, в text не упоминать):
- Витамин D3 — A003, A004
</данные>
```
