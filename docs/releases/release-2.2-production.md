## Порядок выкладки 2.2 (команды запускает владелец)

1. **Копия базы и фото** (сервер): `sudo -iu vitalo /opt/vitalo/app/deploy/scripts/backup.sh` →
   скачать на ноутбук в `C:\VITALO-backups` и сверить контрольные суммы (`sha256sum`).
2. **Код на сервер** (ноутбук): `git push server main`; теги на GitHub: `git push origin main pre-release-2.2 release-2.2`.
3. **Проверка** (сервер): `update.sh --check` — должны быть ровно 2 новые миграции:
   `20261030200000_stage22_catalog_brands` (поля брендов, `merged_into_id`, 2 новые категории типа; только добавляет) и
   `20261030300000_product_short_names` (ничего не меняет: поля есть с 2.1).
4. **Обновление** (сервер): `update.sh --migrate`, затем `healthcheck.sh`.
5. **Перенос категорий** (сервер): `npm run catalog:stage22 -- --allow-production` (только таблица) → сверить с таблицей выше →
   `npm run catalog:stage22 -- --allow-production --apply`. Откат: `--rollback`.
6. **Контент** (сервер): скопировать `VITALO_content.xlsx` в `/tmp`, затем
   `npm run content:load -- --allow-production --file /tmp/VITALO_content.xlsx --skip VM-DUO-120 --skip VM-COLL-CAPS --skip MP-COLL-90`
   (только таблица) → сверить → то же с `--apply`. Откат: `--rollback`.
7. **Проверка**: каталог «По потребности» / «По типу», лента брендов, страница бренда, админка «Бренды» в боевом боте.

Перед каждой командой на боевой базе скрипт спрашивает имя базы — нужно ввести `vitalo`.
