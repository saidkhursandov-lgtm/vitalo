## Что сделано (ветка `stage-2.2`)

- **Миграция** `20261030200000_stage22_catalog_brands` (только добавляет): у брендов — адрес (slug), логотип, страна RU/UZ,
  «Почему [бренд] в VITALO» RU/UZ, «показывать в ленте», порядок; адреса уже существующих брендов заполняются сами
  («NOW Foods» → `now-foods`); страна — из товаров, если у всех товаров бренда она одна. У категорий — `merged_into_id`
  (скрытая старая категория указывает на замену). Две новые категории: «Креатин и аминокислоты», «Протеин и гейнеры».
- **Перенос категорий** — `npm run catalog:stage22` (в `apps/api`):
  - без флагов — только проверка: печатает таблицы, ничего не пишет;
  - `-- --apply` — сначала резервные таблицы `stage22_backup_product_categories` и `stage22_backup_categories`, потом перенос, всё одной транзакцией;
  - `-- --rollback` — всё обратно из резервных таблиц;
  - `-- --set-type SKU=тип` — тип товара вручную.

  Для базы магазина нужен `--allow-production` и ввод имени базы.
- **Mini App:** главная и «Каталог» — «По потребности», «По типу» (одним уровнем, одно нажатие до товаров),
  лента «Проверенные бренды»; страница бренда `/brand/<адрес>`; бренд в карточке товара ведёт на страницу бренда;
  баннер со ссылкой на бренд открывает страницу бренда; блок «Язык» убран из профиля; на 320 px в «По типу» иконка над
  названием, слова не переносятся по буквам.
- **Админка:** раздел «Бренды» (список, адрес, страна, «Почему … в VITALO», лента, порядок, логотип 400×400);
  в карточке товара «По потребности» — несколько галочек, «По типу» — один вариант. Сервер не даст сохранить два типа.
- **Тесты:** API 154 и e2e 796, Mini App 75, админка 35, бот 33 — зелёные.
