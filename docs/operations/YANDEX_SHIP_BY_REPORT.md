# Заказы Яндекса: срок «Отгрузить до» — короткий отчёт

Решение: [DECISIONS.md](DECISIONS.md), S2D-13. Коммит локальный, без push. На сервер я не заходил, на `vitalo_dev` ничего
не запускал. Тесты — только на `vitalo_test`, на подставных ответах: настоящих запросов к Яндексу не было.

## Что было

Сообщение о новом заказе Яндекса складу и администраторам уже приходило и не дублировалось. Срока отгрузки в нём не
было: блок `delivery` ответа Яндекса вырезался целиком, потому что в нём же лежат адрес покупателя и данные курьера.

## Что сверено по документации Яндекса

- Срок лежит в `delivery.shipment` (одна отгрузка, не список): `shipmentDate` в формате `ГГГГ-ММ-ДД`,
  `shipmentTime` — необязательное (`ЧЧ:ММ` или `ЧЧ:ММ:СС`).
- Обязателен ли сам блок `shipment` для каждого заказа, документация не говорит. Поэтому отсутствие срока — не ошибка.

## Что сделано

1. **Из `delivery` берутся только дата и время отгрузки.** Адрес, получатель, телефоны и данные курьера по-прежнему
   не сохраняются нигде: ни в базе, ни в журнале запусков, ни в Telegram. Это проверяет тест.
2. **Сообщение складу и администраторам** (менеджеру и маркетологу не уходит):

   ```
   🟡 Новый заказ Яндекс № 123456789, отгрузить до 14.10.2026 12:00
   OZN-A001 × 2, OZN-A023 × 1
   Банки зарезервированы, можно собирать.
   ```

   Без времени — «отгрузить до 14.10.2026». Если Яндекс срок не прислал или прислал в непонятном виде — заказ создаётся
   как обычно, текст прежний («Новый заказ Яндекса № …»), в «Требует внимания» заказ не попадает.
3. **Админка.** В списке заказов Яндекса — колонка «Отгрузить до», в карточке — строка «Отгрузить до». Пока заказ не
   передан в доставку: красная пометка «просрочено», если день прошёл, и жёлтая «сегодня» — в день отгрузки.
   Если срока нет — «срок не указан Яндексом».
4. **Без дублей — как и раньше.** Одно сообщение на заказ, сколько бы раз он ни пришёл (опрос, вебхук по обоим путям).
   Если Яндекс позже добавит или перенесёт срок, он тихо обновится в карточке, второго сообщения не будет. Ответ без
   срока уже известный срок не стирает.
5. **«Требует внимания»** по-прежнему получают только администраторы.
6. **DRY_RUN:** заказы не создаются и сообщения не уходят — как раньше.

У заказов, созданных до этого обновления, срок появится сам при следующей синхронизации, если заказ ещё попадает в
окно опроса (последние 3 дня). Сообщение по ним повторно не придёт.

## Миграция

`20261016100000_yandex_ship_by` — только добавляет две пустые колонки в таблицу заказов Яндекса (дата и время срока).
Существующие данные не меняются.

## Тесты

- Сервер: быстрые — 114, полные на `vitalo_test` — **742, все прошли** (4 новых). Админка — 26 тестов. Сборки без ошибок.
- Новые тесты: срок с временем и без — в сообщении, карточке и списке; нет блока или битая дата — прежний текст и
  никакого «внимания»; из `delivery` сохраняются только два значения; опрос + вебхук по обоим путям — одно сообщение;
  срок, появившийся или изменившийся позже, обновляется без второго сообщения; DRY_RUN — сообщений нет; получатели —
  только склад и администраторы; «требует внимания» — только администраторы.
- В браузере на тестовой базе: колонка в списке и строка «Отгрузить до 16.10.2026 09:30» в карточке — на месте.

## Как выкатить на сервер

**1. На компьютере — отправить код** (магазин при этом не меняется):

```powershell
cd C:\Users\PC_LENOVO\Documents\VITALO\vitalo
& "C:\Program Files\Git\cmd\git.exe" push server main
```

Хорошо: в конце `main -> main`.

**2. На сервере — резервная копия:**

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/backup.sh
```

Хорошо: строка `База: … проверена`.

**3. Посмотреть, что придёт (ничего не меняет):**

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/update.sh --check
```

Хорошо: в списке новых миграций — `20261016100000_yandex_ship_by` (и больше ничего незнакомого).

**4. Обновить с миграцией** (перед ней скрипт сам делает ещё одну копию базы):

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/update.sh --migrate
```

Хорошо: последняя строка «API отвечает. Готово.»

**5. Проверить:**

```bash
sudo /opt/vitalo/app/scripts/server/healthcheck.sh
```

Хорошо: «ИТОГ: всё в порядке». В админке → «Заказы Яндекса» появилась колонка «Отгрузить до».

**Откат,** если что-то пошло не так: копия базы лежит в `/var/backups/vitalo`; восстановление —
[DEPLOY_RUNBOOK.md](../DEPLOY_RUNBOOK.md), фаза 7.4. Сама миграция только добавляет колонки, старый код с ними работает.

## На домашнем компьютере

Если хотите ту же версию локально — примените миграцию к `vitalo_dev` как обычно, после бэкапа (команды — как в отчёте
Этапа 3, раздел «Миграция»). Для сервера это не обязательно.
