# Payme — подключение (Merchant API)

Разовая оплата заказа из корзины. Без привязки карт и подписок.

## Как это работает

1. Покупатель выбирает «Payme» при оформлении. Способ виден, только когда в админке «Настройки → Оплата» для Payme
   стоит «Работает» (для всех) или «Тест (сотрудники)» — тогда Payme работает только у тех, чей Telegram есть среди
   активных сотрудников, а покупатели видят «Скоро». Включить «Тест» или «Работает» можно, только если ключи есть в `.env`.
2. Заказ создаётся «Ждёт оплаты». Экран `/orders/:id/payme` → кнопка «Оплатить через Payme» открывает
   `checkout.paycom.uz` (в тесте — песочница `test.paycom.uz`, так в документации Payme) + base64(`m=…;ac.order_id=202611030001;a=сумма в тийинах;l=ru|uz;c=https://t.me/<бот>`).
   `order_id` — только цифры номера заказа (так согласовано с Payme): `VTL-20261103-0001` → `202611030001`; сервер понимает и полную запись.
   Ссылка открывается только через `apps/miniapp/src/lib/telegram.ts` (`openLink`).
3. Payme сам вызывает наш сервер: `POST https://api.vitalo.uz/api/payments/payme` (JSON-RPC 2.0, заголовок
   `Authorization: Basic base64("Paycom:" + PAYME_KEY)`).
4. После `PerformTransaction` заказ становится «Оплачен» тем же путём, что и онлайн-подтверждение
   (`OrderLifecycleService.confirmOnlinePayment`): резерв → списание (или банки по FEFO, S2E-2), история «система»,
   сообщение покупателю. Экран Mini App каждые 4 секунды спрашивает статус и показывает «Оплата подтверждена».

| Метод Payme | Что делаем |
| --- | --- |
| CheckPerformTransaction | проверяем заказ и сумму, отдаём чек `detail` (товары с ИКПУ + «Доставка») |
| CreateTransaction | запоминаем транзакцию (`payme_transactions`, состояние 1). У заказа может быть только одна ждущая транзакция |
| PerformTransaction | заказ → «Оплачен» (состояние 2) |
| CancelTransaction | до оплаты: состояние −1, заказ ждёт дальше. После оплаты: состояние −2, заказ отменён, товар вернулся на склад, задача менеджеру `refund` «проверить возврат в Payme Business». После «Передан в доставку» отменить нельзя (−31007) |
| CheckTransaction, GetStatement | отдаём сохранённые данные |
| ChangePassword | не поддерживаем: ключ меняется вручную в `.env` на сервере |

- Повторный вызов с тем же `id` даёт тот же ответ.
- Ошибки: −32504 неверный ключ, −31001 сумма, −31003 нет транзакции, −31007 нельзя отменить, −31008 нельзя выполнить,
  −31050 заказ не найден, −31051 заказ уже оплачен / отменён / время вышло, −31008 у заказа уже есть ждущая транзакция (так ждёт песочница),
  −31053 у товара нет ИКПУ.
- Время: транзакция, не проведённая за 12 часов, отменяется (причина 4). Пока Payme держит деньги (состояние 1), автоотмена
  заказа по резерву (`payment_methods.timeout_minutes`, у Payme 30 минут) ждёт. Без транзакции заказ отменяется как обычно.

## Чек (фискализация)

- У каждого товара в карточке админки — блок «Чек для Payme»: ИКПУ (17 цифр) и код упаковки (tasnif.soliq.uz).
- Если у товара в корзине нет кодов, Payme в оформлении показан неактивным с пояснением, заказ с Payme не создаётся.
- Строка «Доставка» берёт коды из `.env`: `PAYME_DELIVERY_IKPU`, `PAYME_DELIVERY_PACKAGE_CODE`. НДС для всех строк — `PAYME_VAT_PERCENT`
  (0, если магазин не платит НДС).

## Настройки (`.env`, значения — только там)

`PAYME_MERCHANT_ID`, `PAYME_KEY`, `PAYME_TEST_MODE`, `PAYME_DELIVERY_IKPU`, `PAYME_DELIVERY_PACKAGE_CODE`,
`PAYME_VAT_PERCENT`. **Ключ — всегда в одинарных кавычках:** `PAYME_KEY='…'`. В ключе бывает `#`, и без кавычек
всё после него читается как комментарий: сервер отвечает «Недостаточно привилегий», Payme пишет «Сервис поставщика работает
некорректно» (так было 06.11.2026 с боевым ключом). Шаблоны без значений: `.env.example`, `apps/api/.env.production.example`.

## Проверка в песочнице (до выкладки)

1. На ноутбуке в `apps\api\.env`: `PAYME_MERCHANT_ID`, **тестовый** ключ в `PAYME_KEY`, `PAYME_TEST_MODE=true`, коды доставки.
2. Применить миграцию `20261111100000_payme_merchant_api` на `vitalo_dev` (только с разрешения), `start.bat`.
3. В админке: ИКПУ у тестового товара, «Настройки → Оплата» → Payme «Работает».
4. В кабинете песочницы test.paycom.uz указать адрес `https://<адрес туннеля Mini App>/api/payments/payme`
   (меняется при каждом запуске `start.bat`) и пройти все сценарии песочницы.
5. Оформить заказ в тестовом боте @vitalo_store_bot, оплатить тестовой картой, проверить «Оплачен».

### Песочница на боевом сервере (адрес в кабинете не меняем)

В кабинете песочницы уже стоит `https://api.vitalo.uz/api/payments/payme`, поэтому проверка идёт на сервере:

1. В `.env` на сервере: `PAYME_MERCHANT_ID`, **тестовый** ключ в `PAYME_KEY`, `PAYME_TEST_MODE=true`, коды доставки.
2. Выкладка с миграцией `20261111100000_payme_merchant_api` (`update.sh --migrate`, только по решению пользователя).
3. В админке: ИКПУ у товара для теста, «Настройки → Оплата» → Payme «Тест (сотрудники)». Покупатели видят «Скоро».
4. Сотрудник оформляет заказ в боевом боте с Payme, в песочнице проходит все сценарии, оплачивает тестовой картой.
5. Тестовые заказы потом отменить в админке.

Уроки песочницы (05.11.2026, пройдена полностью):
- сумма в песочнице — в **тийинах**: 84 000 сум = `8400000`; «Несуществующий счёт» — с несуществующим номером заказа;
- перед тестами: тип счёта «Одноразовый», статус «Ожидает оплаты»;
- Payme потом сам проверяет два тестовых заказа: на это время в «Настройки → Срок резерва» у Payme ставят до 4320 минут
  (3 суток, до оформления заказов), после проверки возвращают 30.

Для боевого: в Payme Business адрес `https://api.vitalo.uz/api/payments/payme`, боевой ключ и `PAYME_TEST_MODE=false`
в `.env` на сервере.
