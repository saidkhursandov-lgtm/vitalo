# Наклейка для заказов Mini App (75×120 мм) — короткий отчёт

Решение: [DECISIONS.md](DECISIONS.md), S2E-13. Коммиты локальные, без push. На сервер я не заходил, на `vitalo_dev` ничего
не запускал. Тесты — только на `vitalo_test`; запросов к Яндексу в них нет.

## Что сделано

1. **Кнопка «Печать наклейки»** в карточке заказа Mini App — новый блок «Отправка». Открывает страницу печати в обычном
   браузере: формат **75×120 мм**, чёрно-белая, без полей, **одна наклейка на заказ**. У заказов Яндекса такой кнопки нет.
2. **На наклейке:**
   - «VITALO» и дата заказа;
   - крупно номер заказа (`VTL-…`), всегда в одну строку;
   - чёрная плашка «ПРЕДОПЛАЧЕНО»;
   - получатель и телефон;
   - адрес доставки (регион, город, адрес);
   - состав: артикул × количество и короткое название, сверху — сколько всего штук;
   - QR-код с номером заказа;
   - номер накладной службы доставки — если заполнен.

   Цен, себестоимости и номеров банок на наклейке нет.
3. **Поле «Номер накладной службы доставки»** в том же блоке — необязательное (BTS, Яндекс Go и т. п.). Заполнили —
   печатается на наклейке; оставили пустым — строки на наклейке нет.
4. **Кнопка «Тестовая наклейка»** — страница с вымышленными данными, чтобы настроить принтер, не открывая чужой заказ.

## Кто что может

| Роль | Печать наклейки | Номер накладной |
| --- | --- | --- |
| Администратор | да | меняет |
| Склад | да | меняет |
| Менеджер | да | только видит |
| Маркетолог | нет (заказы не видит) | нет |

Остальные права не менялись. Заказы Яндекса, резервирование и сборка банок не затронуты.

## Персональные данные

- Имя, телефон и адрес покупателя есть только на странице печати и на бумаге.
- В журнал аудита пишется **только факт**: «Напечатана наклейка заказа», кто, когда и номер заказа. Имени, телефона и
  адреса там нет — это проверяет тест.
- Страница печати открывается по одноразовой ссылке-билету, как этикетки банок: билет действует 15 минут, годится
  только для этого заказа и перестаёт работать, когда сотрудник вышел из админки. Билет исчезает из адресной строки
  сразу после открытия.
- Печать никому ничего не отправляет и ничего не пишет в журнал ошибок.

## Что я решил сам (проверьте)

1. **Наклейка печатается только для оплаченного и не отменённого заказа** — на ней стоит «ПРЕДОПЛАЧЕНО». Для
   неоплаченного кнопки нет, написано «печатается после подтверждения оплаты».
2. **Каждая печать записывается в журнал** (повторная — тоже), но количество печатей не ограничено.
3. **Номер накладной — короткий номер, не свободный текст:** до 64 символов, буквы, цифры, пробел и знаки `. _ / # № -`.
   Менять можно в любой момент, пока заказ не отменён. Каждое изменение пишется в журнал (сам номер — не персональные данные).
4. **Покупатель номер накладной не видит** — в Mini App он не показывается (клиентская часть не менялась). Если захотите
   показывать его клиенту для отслеживания — скажите, это отдельная небольшая задача.
5. **Что помещается.** Имя — до двух строк, адрес — до трёх, состав — до шести строк. Если позиций больше шести,
   печатаются первые пять и строка «…и ещё N поз. (M шт.) — см. заказ», чтобы ничего не обрезалось молча. Проверено в
   браузере на самом длинном случае: ничего не вылезает за края.
6. **Менеджер печатает наклейку** (как вы и просили), но накладную не меняет.

## Миграция

`20261017100000_order_delivery_waybill` — только добавляет одну пустую колонку «номер накладной» в таблицу заказов.
Существующие данные не меняются.

## Тесты

- Сервер: быстрые — 114, полные на `vitalo_test` — **756, все прошли** (6 новых и 2 строки в общей таблице прав).
  Админка — 29 тестов. Сборки сервера и админки без ошибок.
- Что проверяют новые тесты:
  - содержимое наклейки; накладная печатается только когда заполнена;
  - в журнале аудита — только факт и номер заказа, без имени, телефона и адреса;
  - роли: печать — менеджер, склад, админ; накладная — склад и админ; маркетолог — отказ;
  - только оплаченный и не отменённый заказ; у заказов Яндекса такого пути нет;
  - билет: чужой, подделанный, просроченный, от этикеток банок или после выхода сотрудника — ничего не печатает;
  - накладная: проверка формата, очистка, покупатель её не видит.
- В браузере на тестовой базе: предпросмотр 75×120 мм, блок «Отправка» в карточке, открытие страницы печати по
  ссылке из карточки. **На настоящем принтере я проверить не могу** — это нужно сделать вам (ниже).

## Как проверить печать у себя

1. Карточка оплаченного заказа → блок «Отправка» → **«Тестовая наклейка»** → «Печать».
2. В окне печати: принтер Xprinter, бумага **75×120 мм**, масштаб **100 %**, поля **«Нет»**, колонтитулы выключены.
3. Должно получиться: всё в пределах наклейки, QR-код читается телефоном и показывает номер `VTL-…`, плашка
   «ПРЕДОПЛАЧЕНО» чёрная. Если печать сдвинута или обрезана — пришлите фото наклейки.
4. Затем **«Печать наклейки»** на настоящем заказе.

Настройка бумаги в драйвере принтера — как для этикеток банок: [PRINT_SETUP.md](../PRINT_SETUP.md), только размер 75×120.

## Как выкатить на сервер

**1. На компьютере — отправить код** (магазин при этом не меняется):

```powershell
cd C:\Users\PC_LENOVO\Documents\VITALO\vitalo
& "C:\Program Files\Git\cmd\git.exe" push server main
```

Хорошо: в конце `main -> main`.

**2. На сервере — резервная копия:**

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/backup.sh
```

Хорошо: строка `База: … проверена`.

**3. Посмотреть, что придёт (ничего не меняет):**

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/update.sh --check
```

Хорошо: в списке новых миграций — `20261017100000_order_delivery_waybill`. Если вы ещё не выкатывали срок отгрузки
Яндекса, там же будет `20261016100000_yandex_ship_by` — это нормально, обе только добавляют колонки.

**4. Обновить с миграцией** (перед ней скрипт сам делает ещё одну копию базы):

```bash
sudo -iu vitalo /opt/vitalo/app/deploy/scripts/update.sh --migrate
```

Хорошо: последняя строка «API отвечает. Готово.»

**5. Проверить:**

```bash
sudo /opt/vitalo/app/scripts/server/healthcheck.sh
```

Хорошо: «ИТОГ: всё в порядке». В админке в карточке оплаченного заказа появился блок «Отправка».

**Откат,** если что-то пошло не так: копия базы лежит в `/var/backups/vitalo`; восстановление —
[DEPLOY_RUNBOOK.md](../DEPLOY_RUNBOOK.md), фаза 7.4. Миграция только добавляет колонку, старый код с ней работает.
