# Аудит админ-панели admin.vitalo.uz — задание для Claude Code

Дата аудита: 10.11.2026 · боевая панель на `main` = `5ed1592` (тег `release-6b-1`) · аудит сделан по живой панели под
учёткой администратора и сверен с кодом репозитория. Документ отчёта владельца — «Аудит админ-панели VITALO» (Claude Docs).

Это **задание, а не приказ**. Ты (Claude Code) знаешь проект лучше: если пункт противоречит архитектуре, решению D-xx,
ТЗ или сломает что-то рядом — **измени способ или отложи пункт**, но запиши почему (см. «Как работать»). Цель — чтобы
панель говорила правду и не мешала сотрудникам, а не чтобы выполнить список буква в букву.

Обозначения приоритета: **П0** — искажает решения владельца, делать первым · **П1** — ежедневная работа сотрудников ·
**П2** — рост, когда появится время. Усилия: S — до дня, M — 1–3 дня, L — неделя и больше.

## 0. Как работать с этим заданием

1. **Сначала прочитай** `CLAUDE.md`, `docs/PROGRESS.md` (шапка), `docs/DECISIONS.md` и этот файл целиком. Потом — только те файлы, что
   нужны для текущего пункта.
2. **Ветка:** `stage-admin-audit-2` от актуального `main`. Один пункт — один коммит (или несколько мелких), сообщение по образцу
   проекта. На сервер не выкладывать без команды владельца «выкладывай» — по `docs/DEPLOY_RUNBOOK.md`.
3. **Порядок:** волна 1 (П0) → проверка владельцем → волна 2 (П1) → волна 3 (П2). Внутри волны — сверху вниз, но можно менять
   порядок, если так безопаснее.
4. **Правила проекта действуют полностью:** миграции только добавляющие; заказы и клиентов не удалять; тестовые данные
   на `vitalo_dev` менять только с разрешения; боевая база — никогда без владельца; секреты не трогать.
5. **Свобода решения.** Для каждого пункта в таблицах есть колонка «Предложенный патч». Это предложение по результатам чтения
   кода «со стороны». Если видишь лучший путь — делай по-своему. Если пункт вреден, невозможен или уже сделан иначе —
   **не делай**, а запиши в раздел «Отчёт выполнения» внизу этого файла: `пропущено — причина` или `сделано иначе — как`.
6. **Не ломать соседнее.** Перед правкой каждого файла посмотри, кто его ещё использует (`grep`), и прогони тесты пакета
   (`npm test` в `apps/api`, `apps/admin`; `npm run test:e2e` в `apps/api` — на `vitalo_test`). Красные тесты, которые были
   красными до тебя (например, нестабильный `search.e2e`, вопрос 110), не чинить в этой ветке — отметить.
7. **Проверка в браузере** после каждой волны: локально на тестовом боте (`start.bat`), скриншоты «до/после» в
   `docs/screenshots/admin-audit-2/`. По пунктам, где меняется вид страницы, скриншот обязателен.
8. **Журнал:** после каждого завершённого пункта — субагент `progress-keeper` (обновит `docs/PROGRESS.md`). Решения, которые
   требуют «Да/Нет» владельца, — в `docs/DECISIONS.md` в блок предложений, с номером вопроса.
9. **Вопросы владельцу** задавай пачкой перед началом волны, а не по одному в процессе. Если ответа нет — бери самый безопасный
   вариант (тот, который легко откатить) и помечай в отчёте.
10. Если по ходу найдёшь что-то серьёзное, чего здесь нет, — добавь в раздел «Найдено по ходу» внизу, не чини молча.

## 1. Что показал аудит (кратко)

Панель функционально очень зрелая: 37 разделов, учёт по банкам, синхронизация Яндекса, VITALO AI, аудит, вход через Telegram с
подтверждением устройств. Ошибок в консоли нет, страница грузится за 0,4 с, API без сессии закрыт. Проблемы не в
«функции не хватает», а в **сигналах и шуме**:

- дашборд пишет «ничего срочного нет», пока открыты 15 проблем Яндекс-синка, 2 незавершённые приёмки (одна с 05.11), заказ
  «ожидает оплаты» и 3 товара из листа ожидания с нулём на складе;
- 26 из 27 заказов Mini App «Отменён» — и ни в списке, ни на дашборде не видно, что это автоотмены по истёкшему резерву, а
  не отказ клиентов;
- тестовые бренды, закупки и клиенты перемешаны с боевыми; у них нет флага `is_test`, а удалять запрещено;
- «Низкие остатки» показывают товары с минимумом 0;
- формы перегружены (карточка товара ≈120 полей, 4 независимых «Сохранить»);
- в интерфейсе внутренний жаргон («решение D-36», «подэтап 3.9», «docs/PRINT_SETUP.md», сырые ключи событий);
- у `admin.vitalo.uz` нет Content-Security-Policy и защиты от встраивания в iframe.
